# 004. Zip Slip のエントリを含む ZIP は丸ごと止める

- 状態: 採用

## 背景

ZIP のエントリの名前は、ZIP を作った人が自由に書ける。`../outside.txt` のように上へ抜ける名前や、`C:\outside.txt` のような絶対パスをそのまま書き出すと、配送先フォルダの外にファイルができる。これを Zip Slip と呼ぶ。

次の事情が引っ張り合う。

- Zip Slip のエントリは、普通の ZIP の作成ツールでは作られない。入っていれば、その ZIP は細工されたものとみなせる。
- SharpCompress 0.50.7 も、上へ抜ける名前のエントリを書く直前に `ExtractionException` で止める。ただし止まるのはエントリを一つずつ書いている途中なので、それより前のエントリはすでに書き出されている。
- Windows は、パスの各部分の末尾の空白とピリオドを落として書き出す。名前の文字列だけを調べると、この正規化で形が変わる名前を見落とすおそれがある。
- 実験では、`.. /outside.txt` は配送先の外へは出ず、配送先の中に `outside.txt` として書き出された。Windows が `.. ` を空の部分として扱うためである。`Path.GetFullPath` で求めた書き出し先も、配送先の中にあった。
- `memo.` のように末尾がピリオドの名前は、Mac や Linux で作った普通の ZIP にも入りうる。
- ppapd はデーモンとして動き、利用者は展開の結果をその場では見ていない。Zip Slip に気づけるのは、ppapd が記録し、知らせたときだけである。

## 決定

Zip Slip のエントリが一つでもあれば、その ZIP からは何も書き出さず、配送もしない。`ZipExtractor.Extract` は、書き出しを始める前にすべてのエントリを調べ、Zip Slip のエントリが見つかれば `ZipSlipException` を投げて止まる。デーモンはこの例外を受けてエラーとして記録し、利用者に配送しなかったことを知らせる（PRD の F-4.3）。

Zip Slip のエントリとは、名前に `../` を含むもの、`..\` のように `\` 区切りで上へ抜けるもの、`C:\` や `/` で始まる絶対パスのものをいう。検査は次の二つで行い、どちらかに当たれば Zip Slip とする。

- 名前の文字列の検査: `\` を `/` に置き換えたうえで、`/` で区切った部分のどれかが `..` であるもの、`/` で始まるもの、ドライブ名で始まるもの。
- 書き出し先の検査: 配送先と名前を結合して `Path.GetFullPath` で求めたパスが、配送先の `GetFullPath` に区切り文字を付けたもので始まらないもの。

## 検討した選択肢

| 選択肢 | 採らない理由 |
| --- | --- |
| Zip Slip のエントリだけを捨て、残りを配送する | 細工された ZIP の残りのエントリを利用者に届けてしまう。 |
| 拒否したエントリの一覧を `Extract` の戻り値で返す | 呼び出し側が戻り値を読み捨てると、攻撃の記録が残らない。 |
| SharpCompress の `ExtractionException` に任せる | 止まる前に、それより前のエントリが書き出されている。 |
| 名前の文字列の検査だけにする | Windows のパスの正規化で形が変わる名前を見落とすおそれがある。 |
| 名前のどこかの部分の末尾が空白かピリオドのエントリも止める | 実験では外へ抜けず、書き出し先の検査で守れている。止めると、Mac や Linux で作った普通の ZIP が届かなくなる。 |

## 結果

- Zip Slip のエントリを含む ZIP からは、ファイルが一つも配送先に現れない。
- 正しいエントリまで含めて、その ZIP の中身は利用者に届かない。利用者は送った人に送り直しを頼むか、ZIP を削除することになる。
- `ZipSlipException` という型が、展開の処理とデーモンの間の取り決めになる。
- 末尾が空白かピリオドの名前は止めずに書き出すので、ZIP の中の名前と配送されたファイルの名前が食い違うことがある。
- SharpCompress が Zip Slip の止め方を変えても、この決定は SharpCompress に頼らずに成り立つ。
