# 003. ブラウザ連携は自作のブラウザ拡張として作る

- 状態: 提案

## 背景

ブラウザ連携は、Outlook on the web のページでメールの情報を読み、添付をクリックしてダウンロードさせ（[ADR 002](002-attachments-via-downloads.md)）、保存されたファイルのパスとメールのメタデータをデーモンへ渡す。

次の制約が引っ張り合う。

- 組織の IT 管理者の承認が要る仕組みは使わない。利用者が自分で入れられるものに限る。
- デーモンはダウンロードフォルダの下のパスでファイルを受け取る。ブラウザ連携は、ダウンロードの完了と保存先の絶対パスを知る必要がある。
- ブラウザ拡張の `chrome.downloads` API は、ダウンロードの完了と保存先の絶対パスを知らせる。PoC の観察拡張（`poc/observer-extension`、Manifest V3）は、Outlook.com のページでのメールの観察と、ダウンロードの完了と絶対パスの取得の両方ができた。
- Tampermonkey などの UserScript の API には、ダウンロードの保存先の絶対パスを知る手段が見当たらない。
- ブラウザ拡張は Native Messaging で、ローカルのプログラム（ホスト）と標準入出力でメッセージをやり取りできる。Chrome は、ホストのマニフェストの `allowed_origins` に載っている拡張機能からの接続でだけホストを起動する。PoC では、ホストを現在のユーザーのレジストリ（HKCU）に登録するだけで、管理者の権限なしに呼べた。往復は起動後 2 ミリ秒で、接続が開いている間は 4 分間操作しなくても同じホストのプロセスが動き続けた。
- デーモンへの入力は、メールを開いたとき、ダウンロードが終わったとき、一覧が変わったときに、どれもブラウザ拡張から届く。ブラウザが閉じている間に、デーモンがすることはない。
- デーモンがループバックの HTTP で待ち受けると、同じ PC のほかのプロセスや、ブラウザで開いたほかのページからも要求を送れる。それを防ぐには、`Origin` の検証と、利用者が拡張機能に設定するトークンが要る。

## 決定

ブラウザ連携は、Chrome と Edge で動く自作のブラウザ拡張（Manifest V3）として作る。Outlook on the web のページではコンテンツスクリプトがメールの情報を読んで添付をクリックし、バックグラウンドのサービスワーカーが `chrome.downloads` でダウンロードの完了と保存先のパスを受け取る。

ブラウザ拡張とデーモンは Native Messaging でつなぐ。デーモンはネットワークのポートで待ち受けない。ホストのマニフェストの `allowed_origins` には ppapd のブラウザ拡張の ID だけを書き、インストーラーがそれを現在のユーザーのレジストリに登録する。ブラウザ拡張の ID は、マニフェストの `key` で固定する。

デーモンは、Native Messaging のホストとしてブラウザが起動するプロセスそのものとする。常駐するデーモンは置かず、ホストから別のプロセスへ中継もしない。

## 検討した選択肢

| 選択肢 | 採らない理由 |
| --- | --- |
| Tampermonkey などの UserScript | ダウンロードの保存先の絶対パスを知る手段がなく、デーモンへパスを渡せない。 |
| ブラウザ拡張からデーモンへループバックの HTTP で送る | 同じ PC のほかのプロセスやページからも要求を送れる入口が開く。防ぐには `Origin` の検証とトークンの設定を別に作る必要があり、利用者の手間も増える。 |
| 常駐するデーモンを置き、ホストは名前付きパイプなどでそこへ中継する | ホストとデーモンの間の通り道が、同じ PC のほかのプロセスから呼べる入口になる。Native Messaging を選んで避けた入口を作り直すことになる。 |
| Outlook アドイン | 組織の Microsoft 365 では、アドインの導入を管理者が制限していることがある。ブラウザのダウンロードを扱う API もない。 |

## 結果

- 利用者は、拡張機能をデベロッパーモードで読み込むか、ストアで公開されたものを入れる必要がある。Tampermonkey にスクリプトを貼るだけでは入れられない。
- 拡張機能は Outlook のホストへのアクセス権限と `downloads` 権限を求める。利用者は導入時にその権限を承認する。
- Firefox と Safari は対象外になる。
- ブラウザ拡張は自分の ID をホストに登録できない。拡張機能はホストにつながるまでレジストリにもファイルにも書けず、`allowed_origins` にはワイルドカードも書けないためである。ID を `key` で固定し、その ID をインストーラーが登録する。ストアで公開するときは、ストアが決めた ID に合う `key` をマニフェストに持たせる。
- Chrome と Edge は、Native Messaging のホストを別々のレジストリキー（`HKCU\Software\Google\Chrome\NativeMessagingHosts` と `HKCU\Software\Microsoft\Edge\NativeMessagingHosts`）から探す。インストーラーは両方に登録する。
- デーモンはブラウザが開いている間だけ動き、タスクトレイには常駐しない。
- Chrome と Edge、または複数のプロファイルを同時に使うと、デーモンのプロセスが複数動き、同じ SQLite に書き込む。SQLite は WAL モードで開き、書き込みが重なったときは待つ。同じファイルの二重の配送は、`MessageId` と SHA-256 による重複の除外（PRD の F-6）で防ぐ。HMAC の鍵は、複数のプロセスが同時に初回起動しても一つだけ作られるようにする。
