# ppapd ロードマップ

## 未決事項

影響の大きい順に並べる。決まったものは要件定義書（[PRD.md](PRD.md)）かアーキテクチャ（[ARCHITECTURE.md](ARCHITECTURE.md)）に反映し、ここから消す。

1. **「直近」の範囲**: PRD の F-3.1 で、何分以内、または何通以内を「直近」とするか。待機中の ZIP の記録とパスワード候補をいつ破棄するか。同じ組織で照合するときは候補が増えるので、同じ送信者より短くするか。
2. **メッセージの形式**: PRD の §7 にあるメッセージの項目と応答の形式を定める。
3. **待機中・失敗・不一致・ブロックした ZIP の表示**: PRD の F-2.4 のバッジの色と文言。
4. **末尾が空白かピリオドの名前**: ZIP の中の名前のうち、どこかの部分の末尾が空白かピリオドのものは、Windows で書き出すと名前が変わる（`memo.` は `memo` になり、`a.` と `a` は同じファイルになる）。この食い違いをどう扱うか。外へ抜けないことは PRD の F-4.3 の検査で守られている。
5. **リポジトリ名**: 扱う範囲が PPAP より広くなったので、`ppapd` のままでよいか。
6. **ブラウザ拡張の配布**: ストアで公開するか、デベロッパーモードでの読み込みだけにするか（ADR 003）。
7. **ブロックした ZIP の知らせの文言**: PRD の F-4.7 で配送先フォルダーに置く `<ZIP の名前>.ブロックしました.txt` の中身と、補助のトースト通知に何と書くか。理由（F-4.3、F-4.6）ごとに文を変えるか。

## 後の段で足すテスト

作る段が来たら足す。足したらここから消す。

1. **展開で拒んだ ZIP は圧縮し直さない**: デーモンを作る段で、`ZipExtractor.Extract` が `ZipSlipException` か `ZipTooLargeException` で拒んだ ZIP について、`ZipRepacker.Repack` が呼ばれないことを確かめる。`Repack` は Zip Slip の名前も展開の上限も調べず、`Extract` を通った ZIP だけを受け取る前提で作っている（PRD の F-4.3、F-4.4、F-4.6）。
