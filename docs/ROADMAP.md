# ppapd ロードマップ

## 未決事項

影響の大きい順に並べる。決まったものは要件定義書（[PRD.md](PRD.md)）かアーキテクチャ（[ARCHITECTURE.md](ARCHITECTURE.md)）に反映し、ここから消す。

1. **規則に一致しないメールの扱い**: PRD の F-1.8 で自動配送の対象にならないメールの添付を、利用者がどう配送させるか。Outlook の画面の添付のダウンロードボタンの近くに「プロジェクトフォルダへ配置して展開」のような操作を埋め込み、利用者が選んだ添付だけを配送する方法がある。
2. **ダウンロードフォルダのファイルの扱い**: 配送した後、ダウンロードフォルダのファイルを消す（移動）か残す（コピー）か（PRD の F-5）。
3. **OneDrive のフォルダ共有リンク**: フォルダをダウンロードすると ZIP にまとめられるという前提（PRD の R-5）を確かめる。
4. **「直近」の範囲**: PRD の F-3.1 で、何分以内、または何通以内を「直近」とするか。待機中の ZIP の記録とパスワード候補をいつ破棄するか。同じ組織で照合するときは候補が増えるので、同じ送信者より短くするか。
5. **メッセージの形式**: PRD の §7 にあるメッセージの項目と応答の形式を定める。
6. **待機中・失敗・不一致の表示**: PRD の F-2.4 のバッジの色と文言。
7. **リポジトリ名**: 扱う範囲が PPAP より広くなったので、`ppapd` のままでよいか。
8. **ブラウザ拡張の配布**: ストアで公開するか、デベロッパーモードでの読み込みだけにするか（ADR 003）。
