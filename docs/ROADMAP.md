# ppapd ロードマップ

## 未決事項

影響の大きい順に並べる。決まったものは要件定義書（[PRD.md](PRD.md)）かアーキテクチャ（[ARCHITECTURE.md](ARCHITECTURE.md)）に反映し、ここから消す。

1. **デーモンとホストの関係**: Chrome が起動する Native Messaging のホストのプロセスがそのままデーモンになるか、常駐するデーモンへ中継するか。Chrome と Edge、または複数のプロファイルから同時につながったときに、配送台帳への書き込みをどうまとめるか（ADR 003）。
2. **ダウンロードとメールの対応付け**: リンクを開いた先は別のタブになり、ログイン画面を挟むこともある。どのダウンロードがどのメールのリンクから始まったかを、どう突き止めるか（PRD の F-1.6）。
3. **自動で配送するメールの範囲**: 添付をダウンロードするたびに配送するか（PRD の F-1.6）、`projects` の規則に一致したメールに絞るか。署名の画像ファイルなど、配送したくない添付をどう除くか。自動で配送する代わりに、Outlook の画面の添付のダウンロードボタンの近くに「プロジェクトフォルダへ配置して展開」のような操作を埋め込み、利用者が選んだ添付だけを配送する方法もある。
4. **ダウンロードフォルダのファイルの扱い**: 配送した後、ダウンロードフォルダのファイルを消す（移動）か残す（コピー）か（PRD の F-5）。
5. **OneDrive のフォルダ共有リンク**: フォルダをダウンロードすると ZIP にまとめられるという前提（PRD の R-5）を確かめる。
6. **「直近」の範囲**: PRD の F-3.1 で、何分以内、または何通以内を「直近」とするか。待機中の ZIP の記録とパスワード候補をいつ破棄するか。同じ組織で照合するときは候補が増えるので、同じ送信者より短くするか。
7. **メッセージの形式**: PRD の §7 にあるメッセージの項目と応答の形式を定める。
8. **待機中・失敗・不一致の表示**: PRD の F-2.4 のバッジの色と文言。
9. **リポジトリ名**: 扱う範囲が PPAP より広くなったので、`ppapd` のままでよいか。
10. **ブラウザ拡張の配布**: ストアで公開するか、デベロッパーモードでの読み込みだけにするか（ADR 003）。
