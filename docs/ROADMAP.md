# ppapd ロードマップ

## 未決事項

影響の大きい順に並べる。決まったものは要件定義書（[PRD.md](PRD.md)）かアーキテクチャ（[ARCHITECTURE.md](ARCHITECTURE.md)）に反映し、ここから消す。

1. **待機中・失敗・不一致の表示**: PRD の F-2.4 のバッジの色と、待機中・解凍失敗・不一致のバッジの語。ブロックした ZIP のバッジの色。
2. **末尾が空白かピリオドの名前**: ZIP の中の名前のうち、どこかの部分の末尾が空白かピリオドのものは、Windows で書き出すと名前が変わる（`memo.` は `memo` になり、`a.` と `a` は同じファイルになる）。この食い違いをどう扱うか。外へ抜けないことは PRD の F-4.3 の検査で守られている。
3. **リポジトリ名**: 扱う範囲が PPAP より広くなったので、`ppapd` のままでよいか。
4. **ブラウザ拡張の配布**: ストアで公開するか、デベロッパーモードでの読み込みだけにするか（ADR 003）。

作る段が来たら作る。作ったら要件定義書に書き、ここから消す。

1. **直近の範囲の設定**: PRD の F-3.1 の直近の範囲（同じ `ConversationId` と同じ送信者で 24 時間、同じ組織で 1 時間）と、F-3.2 と F-3.6 の記録を消すまでの時間（24 時間）を、`rules.yaml` で上書きできるようにする。いまはどれも既定値だけで、コードでは `PairingWindow` の定数にまとめてある。
