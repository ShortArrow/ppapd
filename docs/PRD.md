# ppapd 要件定義書

ppapd は、Outlook on the web で受け取ったファイルを、プロジェクト・送信者・受信日ごとのフォルダへ自動で配送する Windows 用の常駐ツールである。ファイルの受け取り経路は、メールの添付、パスワード付き ZIP とパスワードを別々に送る PPAP、本文のダウンロードリンクの三種類を扱う。

ppapd は PPAP を受け取る側の手作業も減らすが、PPAP の利用を推奨するものではない。

## 1. 目的

メールで受け取ったファイルを、案件ごとのフォルダに置くまでの次の手作業をなくす。

1. 添付を保存する、またはリンク先からダウンロードする
2. PPAP であれば、パスワードのメールを探して解凍する
3. ZIP であれば展開する
4. プロジェクト・送信者・日付のフォルダを作り、そこへ移す

### 1.1 前提と制約

- Microsoft Graph API、Azure AD（Entra ID）のアプリ登録、テナント管理者の同意など、組織の IT 管理者の承認が要る仕組みは使わない。
- 利用者が自分の PC に導入できるものだけで完結させる。ブラウザ上で動く部品と、ユーザー権限で動くローカルデーモンの二つで構成する。
- デーモンはインターネットにも Outlook on the web にも接続しない。メールとファイルの取得はブラウザ側が行う。
- 対応 OS は Windows のみとする。
- デーモンは .NET の最新 LTS 版を対象にする。新しい LTS 版が出たら、現行版のサポートが終わる前に移行する。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| ブラウザ連携 | Outlook on the web 上で動き、メールの情報とファイルをデーモンへ渡す部品 |
| デーモン | ローカルで常駐し、展開と配送を行う C# プロセス |
| 受け取り経路 | ファイルがデーモンに届くまでの道筋。§4 の R-1〜R-5 |
| 配送 | ファイルを配送先フォルダへ書き出すこと |
| プロジェクトルート | 配送先フォルダを作る起点のフォルダ |
| 配送台帳 | 配送済みのファイルと配送先を記録する SQLite データベース |
| ダウンロードフォルダ | 添付とダウンロードリンクの受け取りに使う、ブラウザの既定ダウンロードフォルダの下の固定フォルダ |
| ZIP メール | パスワード付き ZIP が添付されたメール |
| パスワードメール | ZIP のパスワードが本文に書かれたメール |
| ペアリング | ZIP メールとパスワードメールを対応付けること |

## 3. 配送先

配送先は次の形で組み立てる。

```
<プロジェクトルート>\<プロジェクト名>\<送信者名>\<受信日 yyyyMMdd>\
```

| 要素 | 決め方 |
| --- | --- |
| プロジェクトルート | `rules.yaml` の `projects_root` |
| プロジェクト名 | `rules.yaml` の `projects` を上から評価し、最初に一致した規則の `project`。どれにも一致しなければ `unsorted_project` |
| 送信者名 | `rules.yaml` の `senders` で送信者アドレスまたはドメインに付けた別名。別名がなければ送信者ドメイン |
| 受信日 | ファイルを含む、またはリンクを含むメールの受信日 |

ZIP は展開し、ZIP 内のフォルダ構成を保ったまま配送先の下に置く。ZIP 以外のファイルはそのまま置く。

## 4. 受け取り経路

| ID | 経路 | 扱い |
| --- | --- | --- |
| R-1 | ZIP 以外の添付 | そのまま配送する |
| R-2 | パスワードのない ZIP の添付 | 展開して配送する |
| R-3 | パスワード付き ZIP の添付（PPAP） | パスワードメールとペアリングし、解凍して配送する |
| R-4 | 本文のダウンロードリンク | 利用者がブラウザでダウンロードし、ダウンロードフォルダに保存されたファイルを配送する |
| R-5 | 本文の OneDrive の共有リンク | R-4 と同じ。フォルダの共有リンクは ZIP にまとめてダウンロードされるので、R-2 と同じく展開する |

R-4 と R-5 では、リンク先のログインや認証は利用者がブラウザで行う。ダウンロードしたファイルが ZIP であれば、添付の ZIP と同じく R-2 または R-3 の扱いにする。

## 5. 機能要件

### F-1. ブラウザ連携: 抽出と送信

| ID | 要件 |
| --- | --- |
| F-1.1 | メールを開いたとき、`MessageId`、`ConversationId`、送信者アドレス、件名、本文、受信日時を取得する。 |
| F-1.2 | 添付は、Outlook の画面のダウンロードでダウンロードフォルダに保存させる。本文に埋め込まれた画像は対象外とする。理由は [ADR 002](adr/002-attachments-via-downloads.md) にある。 |
| F-1.3 | 本文から正規表現でパスワード候補を抽出する。既定のパターンは `パスワード[:：\s]+([^\s]+)` などとし、利用者が追加・変更できる。 |
| F-1.4 | パスワード候補のあるメールの本文とメタデータを、デーモンへ送る。 |
| F-1.6 | 添付のダウンロード、または本文のリンクから始まったダウンロードが完了したら、ダウンロードフォルダの下のパスと、添付またはリンクを含むメールのメタデータをデーモンへ送る。 |

### F-2. ブラウザ連携: 配送状態の表示

| ID | 要件 |
| --- | --- |
| F-2.1 | メール一覧に表示中のアイテムを監視し、その `MessageId` 一覧の配送状態をデーモンにまとめて問い合わせる。 |
| F-2.2 | 配送済みのメールに `[配送済]` バッジを表示する。 |
| F-2.3 | バッジをクリックすると、デーモンが配送先フォルダをエクスプローラーで開く。 |
| F-2.4 | 待機中、解凍失敗、不一致のメールは、それぞれの状態がわかる表示にする。 |

### F-3. デーモン: PPAP のペアリング（R-3）

| ID | 要件 |
| --- | --- |
| F-3.1 | 直近に届いたメールの間で、次の順に相手を探して ZIP とパスワードを対応付ける。(1) 同じ `ConversationId`、(2) 同じ送信者、(3) 同じ組織。同じ送信者かどうかは送信者アドレスの HMAC-SHA256 で、同じ組織かどうかは送信者ドメインの HMAC-SHA256 で比べる（S-6）。 |
| F-3.2 | 片方しか届いていない間は、ZIP もパスワードも保持しない。保持するのは参照（MessageId、添付 ID、ZIP の SHA-256、本文の SHA-256）だけとし、配送台帳と同じ SQLite に記録する。 |
| F-3.3 | もう片方が届いたら、待機していた側の ZIP または本文をブラウザ連携に再取得させる。 |
| F-3.4 | 再取得した ZIP と本文の SHA-256 が記録と一致しなければ解凍せず、不一致として記録する。 |
| F-3.5 | パスワード候補が複数あるときは、解凍に成功するまで順に試す。 |

待機中の記録は参照だけなので、デーモンを再起動しても失われない。

ペアリングの状態遷移は次のとおり。

| Given | When | Then |
| --- | --- | --- |
| 対応するメールが未着 | ZIP メールを受け取る | ZIP 待機（パスワード待ち）になる |
| 対応するメールが未着 | パスワードメールを受け取る | パスワード待機（ZIP 待ち）になる |
| ZIP 待機 | 対応するパスワードメールを受け取る | ZIP の再取得を要求する |
| パスワード待機 | 対応する ZIP メールを受け取る | パスワードメール本文の再取得を要求する |
| 再取得を要求中 | 再取得した内容の SHA-256 が記録と一致する | 解凍を試す |
| 再取得を要求中 | 再取得した内容の SHA-256 が記録と一致しない | 不一致になり、解凍しない |
| 解凍を試す | いずれかの候補で成功する | 配送する |
| 解凍を試す | すべての候補で失敗する | 解凍失敗になり、新しいパスワード候補を待つ |

### F-4. デーモン: ZIP の展開

| ID | 要件 |
| --- | --- |
| F-4.1 | SharpCompress で、暗号化のない ZIP と、ZipCrypto・AES-256 で暗号化された ZIP を展開する。 |
| F-4.2 | ZIP 内のファイル名の文字コードを判定する。UTF-8 フラグがあれば UTF-8、なければ CP932 として扱う。 |
| F-4.3 | ZIP 内のパスが配送先フォルダの外を指すエントリ（Zip Slip）は書き出さず、エラーとして記録する。 |

### F-5. デーモン: ダウンロードの受け取り

| ID | 要件 |
| --- | --- |
| F-5.1 | ダウンロードフォルダの下を指すパスだけを受け付ける。`..` やシンボリックリンクなどで外を指すパスは拒む。 |
| F-5.2 | 受け取ったファイルは §3 の配送先へ配送する。配送先を決めるメタデータには、添付またはリンクを含むメールのものを使う。 |

### F-6. デーモン: 配送

| ID | 要件 |
| --- | --- |
| F-6.1 | §3 の規則で配送先を決め、フォルダがなければ作る。 |
| F-6.2 | 配送先はローカルドライブと SMB 共有（UNC パス）に対応する。 |
| F-6.3 | 配送先に同名ファイルがあれば上書きせず、`報告書_1.pdf` のように連番を付ける。 |
| F-6.4 | 配送が完了したら、`MessageId`、ファイルの SHA-256、配送先パス、ファイル名一覧を配送台帳に記録する。 |
| F-6.5 | 同じ `MessageId` から同じ SHA-256 のファイルを再び受け取ったら、配送しない。 |

## 6. 設定ファイル（`rules.yaml`）

### 6.1 例

```yaml
projects_root: '\\nas01\Share\Projects'
unsorted_project: '_Unsorted'
download_dir: '%USERPROFILE%\Downloads\ppapd'

senders:
  - domain: "example.co.jp"
    name: "ExampleCorp"
  - address: "someone@example.net"
    name: "ExampleNet-Someone"

projects:
  # 件名の案件番号【P-12345】をそのままプロジェクト名にする
  - project: '{Capture:1}'
    match:
      from_domain: "example.co.jp"
      subject_regex: '【(P-\d{5})】'

  # 請求書・見積書は Accounting にまとめる
  - project: 'Accounting'
    match:
      subject_regex: '(?:請求書|見積書)'
```

この例では、ExampleCorp から件名「【P-12345】図面送付」で 2026 年 11 月 12 日に届いた添付は、`\\nas01\Share\Projects\P-12345\ExampleCorp\20261112\` に配送される。

### 6.2 項目

| キー | 意味 |
| --- | --- |
| `projects_root` | プロジェクトルート |
| `unsorted_project` | どの規則にも一致しないときのプロジェクト名 |
| `download_dir` | ダウンロードフォルダ。ブラウザの既定ダウンロードフォルダの下に置く |
| `senders[].domain` | 送信者ドメインとの完全一致 |
| `senders[].address` | 送信者アドレスとの完全一致。`domain` より優先する |
| `senders[].name` | 送信者名として使う別名 |
| `projects[].project` | プロジェクト名。`{Capture:n}` で `subject_regex` の n 番目のキャプチャを参照できる |
| `projects[].match.from_domain` | 送信者ドメインとの完全一致 |
| `projects[].match.subject_regex` | 件名に対する .NET 正規表現 |

`match` に複数の条件を書いた場合は、すべてを満たしたときに一致とする。プロジェクト名と送信者名のうちファイル名に使えない文字は置き換える。

## 7. API

デーモンは `127.0.0.1:18080` でのみ待ち受ける。

| メソッドとパス | 用途 |
| --- | --- |
| `POST /api/process` | パスワード候補のあるメールのメタデータと本文を受け取る |
| `POST /api/download` | ダウンロードフォルダの下のパスと、添付またはリンクを含むメールのメタデータを受け取る |
| `POST /api/status` | `MessageId` の一覧を受け取り、それぞれの配送状態を返す |
| `POST /api/reveal` | `MessageId` を受け取り、配送先フォルダをエクスプローラーで開く |

## 8. セキュリティ要件

| ID | 要件 |
| --- | --- |
| S-1 | ループバックアドレス `127.0.0.1` のみにバインドし、外部からの接続を受け付けない。 |
| S-2 | すべてのリクエストで `Origin` ヘッダーが `https://outlook.office.com` と完全一致することを検証する。 |
| S-3 | デーモンの初回起動時に Bearer トークンを生成し、すべてのリクエストで検証する。利用者はこのトークンをブラウザ連携に設定する。 |
| S-4 | 本文とパスワードは、受け取ったリクエストの処理中にだけメモリに置き、ディスク、配送台帳、ログには残さない。 |
| S-5 | `POST /api/reveal` は配送台帳に記録された配送先だけを開く。リクエストで任意のパスを指定させない。 |
| S-6 | メールアドレスと、そのドメインは、それぞれ別に HMAC-SHA256 を取って記録する。鍵はデーモンの初回起動時に生成し、配送台帳とは別のファイルに Windows の DPAPI で保護して保存する。平文のアドレスとドメインはリクエストの処理中にだけメモリに置き、ディスク、配送台帳、ログには残さない。例外は、§3 の送信者名としてフォルダ名と配送台帳の配送先パスに残る別名とドメインだけとする。 |
| S-7 | `POST /api/download` は F-5.1 の範囲のパスだけを受け付ける。 |

## 9. MVP の範囲

| 項目 | MVP で実装する | MVP では実装しない |
| --- | --- | --- |
| 受け取り経路 | R-1〜R-5 | デーモン自身がリンク先からダウンロードすること |
| 圧縮形式 | ZIP（暗号化なし、ZipCrypto、AES-256） | 7z、RAR、パスワード付き PDF |
| ペアリング | 同じ `ConversationId`、同じ送信者、同じ送信者ドメイン | 件名の類似度（レーベンシュタイン距離など）による照合 |
| 配送先 | ローカルドライブ、SMB 共有 | Box、Google Drive などのクラウドストレージ |
| UI | 一覧のバッジ、トースト通知 | 設定用の GUI（設定は `rules.yaml` の編集で行う） |
